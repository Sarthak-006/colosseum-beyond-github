# Narrative classification (engine)

Map the project to a **primary category**, then prefer the **default narrative spine** unless evidence says otherwise.

| Project type (examples) | Default narrative spine | Avoid |
| ----------------------- | ------------------------ | ----- |
| AI agents / automation | Verifiable or practical coordination onchain | "AI platform" vagueness |
| Consumer app | Crypto-native UX, speed, cost, ownership moment | Spec sheet in first touch |
| Trading / analytics | Decision quality, risk transparency, edge cases | Guaranteed returns language |
| Wallet / custody UX | Ownership, recovery, human-centered safety | Buzzword "revolutionary" |
| DePIN | Real-world measurement, incentives, trust boundaries | Hand-wavy "IoT on blockchain" |
| Gaming | Player economics, distribution, fun first | Token-first pitch |
| Social / creator | Audience ownership, portable reputation | Generic "web3 social" |
| ZK / privacy | Who it protects and from what | Academic dump without user |
| Stable / payments | When and for whom settlement matters | Ignoring compliance tone where needed |

## Bad vs good (structure)

| Bad | Good |
| --- | ---- |
| "AI platform for Solana users" | "Agents that settle tasks onchain with auditable outcomes" |
| "Next-gen DEX" | "Concentrated liquidity for X with Y risk explicitly bounded because …" |
| "Better UX" | "Your mom can do Z in 60s: here's the flow" |

## Three-variant rule

Always produce **Technical**, **Visionary**, **Meme-native** (if authentic). Rank for **this** team.

## Solana-specific hooks (when true)

- Fees, finality, parallelization, composability, or ecosystem distribution—**only** where factually grounded for the project.
